1. RESUMO EM 30 SEGUNDOS
======================================================================

"O CineAnchieta e um sistema web para acompanhar filmes e series. O usuario
cadastra um titulo, escolhe o formato e acompanha o status: quero ver,
assistindo ou assisti. Na Aula 4 o projeto ganhou CRUD completo no MySQL:
cadastrar, mudar status, editar e remover, tudo salvo no banco. A API usa
uma dona fixa, a Ana, para simular o login que ainda nao existe. O projeto
usa TypeScript, Vite, Express e MySQL."

4. O QUE MUDOU NA AULA 4
======================================================================

ROTAS

- GET /api/titulos -> 200
- GET /api/titulos/:id -> 200 ou 404
- POST /api/titulos -> 201 ou 400
- PATCH /api/titulos/:id/status -> 204, 400 ou 404
- PUT /api/titulos/:id -> 200, 400 ou 404
- DELETE /api/titulos/:id -> 204 ou 404

DECISOES IMPORTANTES

- USUARIO_FIXO = 1 simula a Ana ate o login da Aula 5.
- O titulo 7 e do Bruno, entao responde 404 para a Ana.
- PATCH grava assistido_em = NOW() ao concluir e NULL ao reabrir.
- PUT usa COALESCE(?, titulo) para nao apagar o nome sem querer.
- Todas as consultas usam ? para evitar SQL injection.
- A API valida os dados; o HTML apenas ajuda o usuario.

BANCO

- 4 tabelas: usuarios, titulos, generos e titulo_genero.
- 2 usuarios: Ana e Bruno.
- 7 titulos: 6 da Ana e 1 do Bruno.
- A tela mostra 6; o titulo 7 responde 404.

OBSERVACAO DO AMBIENTE

- O projeto foi escrito para MySQL 8.
- Neste computador usamos XAMPP com MariaDB 10.4.
- A unica diferenca pratica foi a collation do script:
  utf8mb4_unicode_ci no lugar de utf8mb4_0900_ai_ci.

6. PERGUNTAS PROVAVEIS (respostas curtas)
======================================================================

1. O que e CRUD?

   Create, Read, Update e Delete: criar, ler, atualizar e apagar.
   No projeto: POST, GET, PUT/PATCH e DELETE.

2. Por que o titulo 7 da 404 se ele existe?

   Porque pertence ao Bruno. A consulta filtra por usuario_id e responde
   404 para nao revelar dados de outra pessoa.

3. Por que existe USUARIO_FIXO?

   Porque a Aula 4 ainda nao tem login. A constante 1 simula a Ana; na
   Aula 5 ela sera trocada pelo usuario autenticado.

4. Qual a diferenca entre PUT e PATCH?

   PATCH altera so o status. PUT altera o titulo. Cada rota tem uma
   responsabilidade.

5. Por que POST devolve 201 e PATCH/DELETE devolvem 204?

   201 significa criado e inclui o registro novo. 204 significa sucesso
   sem conteudo para devolver.

6. Como o projeto evita SQL injection?

   Todas as consultas usam placeholders ?. O mysql2 envia o comando e os
   valores separados; o texto do usuario nao vira SQL.

7. Por que validar no servidor se o HTML ja tem maxlength?

   Porque a API pode ser chamada direto, sem passar pela pagina. A
   validacao do servidor e a que vale de verdade.

8. Como funciona o "Em breve"?

   A data de lancamento e comparada com a data de hoje em formato
   AAAA-MM-DD. Se for futura, o titulo ganha a etiqueta.

9. O que e o assistido_em?

   A data em que o titulo foi concluido. O PATCH grava NOW() ao marcar
   assisti e NULL ao reabrir.

10. O que e COALESCE?

    Uma funcao SQL que devolve o primeiro valor nao nulo. No PUT,
    COALESCE(?, titulo) mantem o nome antigo se nenhum novo for enviado.

11. Como voce testou?

    npm run verificar na raiz e em api/, npx vite build, chamadas reais
    na API e testes do CRUD no MySQL. Ainda nao ha testes automatizados.

12. O que falta para o projeto?

    Login real (Aula 5), leitura de generos (Aula 6), testes automatizados,
    modal de edicao, confirmacao antes de remover e deploy.
